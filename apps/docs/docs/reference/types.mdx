All types live in the package `com.jantursky.crease`. The generated API docs are on [javadoc.io](https://javadoc.io/doc/io.github.jantursky/crease).

`Hinge`, `Fold` and `FoldState` are plain classes, not data classes, so the library can add to them without breaking binary compatibility. They implement `equals`, `hashCode` and `toString`.

## HingeStatus

```kotlin
public enum class HingeStatus { Closed, PartiallyOpen, FullyOpen }
```

How far the hinge is open, as the platform reports it.

## Hinge

```kotlin
public class Hinge(public val status: HingeStatus, public val angle: Float?)
```

| Property | Type | Description |
| --- | --- | --- |
| `status` | `HingeStatus` | Whether the hinge is shut, half open or fully open. |
| `angle` | `Float?` | Degrees: 0 when shut, 180 when flat. `null` when the device has no angle sensor. |

## FoldOrientation

```kotlin
public enum class FoldOrientation { Vertical, Horizontal }
```

A vertical fold splits the window into a left and a right half. A horizontal fold splits it into a top and a bottom half.

## Fold

```kotlin
public class Fold(
    public val bounds: Rect,
    public val orientation: FoldOrientation,
    public val isSeparating: Boolean,
    public val isOccluding: Boolean,
)
```

| Property | Type | Description |
| --- | --- | --- |
| `bounds` | `Rect` | The fold in window coordinates, in pixels. A seamless panel reports zero width. |
| `orientation` | `FoldOrientation` | Direction of the fold line. |
| `isSeparating` | `Boolean` | Content should stay on one side: the device is half open, or there is a physical gap. |
| `isOccluding` | `Boolean` | The fold hides what is drawn beneath it. |

## Posture

```kotlin
public enum class Posture { Closed, Flat, Book, Tabletop }
```

| Value | Meaning |
| --- | --- |
| `Closed` | The hinge is shut. |
| `Flat` | A phone, a desktop window, or a foldable lying open. |
| `Book` | Half open with a vertical fold, held like a book. |
| `Tabletop` | Half open with a horizontal fold, standing like a laptop. |

See [postures and the hinge](/guides/postures-and-hinge) for the exact rules.

## FoldState

```kotlin
public class FoldState(
    public val hinge: Hinge?,
    public val folds: List<Fold>,
    public val cutouts: List<Rect>,
)
```

| Property | Type | Description |
| --- | --- | --- |
| `hinge` | `Hinge?` | `null` when the device has no hinge or has not reported it yet. |
| `folds` | `List<Fold>` | Folds across the window, usually zero or one. |
| `cutouts` | `List<Rect>` | Camera and sensor housings, in window coordinates and pixels. |
| `fold` | `Fold?` | The first fold, or `null`. |
| `posture` | `Posture` | The current posture. |

### Factories

| Factory | Parameters | Description |
| --- | --- | --- |
| `FoldState.None` | none | No hinge, no folds, no cutouts. |
| `FoldState.closed()` | none | A foldable that is shut. |
| `FoldState.flat(windowSize, orientation, foldWidth)` | `Size`, `FoldOrientation = Vertical`, `Float = 0f` | A foldable lying open. |
| `FoldState.book(windowSize, angle, foldWidth)` | `Size`, `Float = 90f`, `Float = 0f` | Half open, vertical fold in the middle. |
| `FoldState.tabletop(windowSize, angle, foldWidth)` | `Size`, `Float = 90f`, `Float = 0f` | Half open, horizontal fold in the middle. |

`windowSize` and `foldWidth` are in pixels, `angle` in degrees.

## CoverDisplayState

Package `com.jantursky.crease.cover`, artifact `crease-cover`.

```kotlin
public sealed interface CoverDisplayState {
    public data object Unsupported : CoverDisplayState
    public data object Unavailable : CoverDisplayState
    public data object Available : CoverDisplayState
    public data object Active : CoverDisplayState
}

public val CoverDisplayState.isSupported: Boolean
```

Whether the outer display can show your content right now. The system decides, so the main UI has to work in every state.

| Value | Description |
| --- | --- |
| `Unsupported` | This device or system has no way to show app content on an outer display. Nothing ever changes it. |
| `Unavailable` | Supported, but not possible right now, for example because the device is closed or the app is not in front. |
| `Available` | The system would present the content if `CoverDisplay` asked for it. |
| `Active` | The content is on the outer display. |

`isSupported` is `true` unless the state is `Unsupported`. See the [cover display guide](/guides/cover-display).

## CameraDirections

Package `com.jantursky.crease.cover`, artifact `crease-cover`.

```kotlin
public class CameraDirections(
    public val forwardFacing: List<CameraDescriptor>,
    public val backwardFacing: List<CameraDescriptor>,
)
```

Which cameras face the viewer and which face away, from the point of view of the screen the UI is on. On a foldable the answer changes with the display.

| Property | Type | Description |
| --- | --- | --- |
| `forwardFacing` | `List<CameraDescriptor>` | Cameras that capture the scene in front of the display. |
| `backwardFacing` | `List<CameraDescriptor>` | Cameras that capture the scene behind the display. |

## CameraDescriptor

```kotlin
public class CameraDescriptor(
    public val id: String,
    public val name: String,
    public val type: String,
    public val position: CameraPosition,
)
```

One camera, as much as is needed to find it again in the platform's camera API.

| Property | Type | Description |
| --- | --- | --- |
| `id` | `String` | The platform's unique id of the device. On iOS it matches `AVCaptureDevice.uniqueID`. |
| `name` | `String` | The device name. |
| `type` | `String` | The platform's device type, on iOS the `AVCaptureDeviceType` string. |
| `position` | `CameraPosition` | Where the camera sits on the device. |

## FoldController

Package `com.jantursky.crease.test`, artifact `crease-test`. Returned by `setContentWithFold()`.

```kotlin
public class FoldController {
    public val state: FoldState
    public fun update(state: FoldState)
    public fun moveTo(posture: Posture, windowSize: Size, angle: Float = ..., foldWidth: Float = ..., orientation: FoldOrientation = ...)
    public fun play(states: List<FoldState>, onEach: (FoldState) -> Unit = ...)
}
```

Changes the fold state while the composition stays alive, so remembered state survives. See [previews and tests](/guides/previews-and-tests).

| Member | Description |
| --- | --- |
| `state` | The fold state the content currently sees. |
| `update(state)` | Sets the state. |
| `moveTo(posture, windowSize, ...)` | Builds the state for a posture in a window and sets it. |
| `play(states, onEach)` | Sets each state in turn, calling `onEach` after each one. |

## FoldPreset

Package `com.jantursky.crease.test`, artifact `crease-test`.

```kotlin
public class FoldPreset(public val windowSize: Size, public val foldWidth: Float) {
    public fun closed(): FoldState
    public fun flat(orientation: FoldOrientation = ...): FoldState
    public fun book(angle: Float = ...): FoldState
    public fun tabletop(angle: Float = ...): FoldState
    public fun state(posture: Posture, angle: Float = ..., orientation: FoldOrientation = ...): FoldState
}
```

Builds a fold state for every posture in a window of `windowSize` with a fold `foldWidth` pixels wide. The values are plain test fixtures, not measurements of a particular device.

## FoldStatePresets

Package `com.jantursky.crease.test`, artifact `crease-test`.

```kotlin
public object FoldStatePresets {
    public val Seamless: FoldPreset
    public val Divided: FoldPreset
}
```

| Value | Description |
| --- | --- |
| `Seamless` | A foldable whose panel is one piece across the fold: the window is 2520 by 1920 px and the fold takes no space. |
| `Divided` | A foldable with a 40 px division between two screens: same window, and the fold occludes content. |

## FoldLayoutClass

public data class FoldLayoutClass(

The window size class and the Crease `Posture` together, so one `when` can pick a layout. Test the size class with `isWidthAtLeastBreakpoint` and `isHeightAtLeastBreakpoint`. See [Material3 adaptive](/guides/material3-adaptive).
